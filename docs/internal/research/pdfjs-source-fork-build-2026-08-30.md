# Building pdfjs-dist from a source fork (issue #156)

Research for [evb0110/evb-viewer#156](https://github.com/evb0110/evb-viewer/issues/156), part of #150. Read-only: pdf.js at tag `v5.7.284` in `/Users/evb/npm-repos/pdf.js`, and this checkout. No build was run; timings come from Mozilla's own release runs.

## 1. What the pdf.js build needs

**Toolchain.** Node `>=22.13.0 || >=24` (`package.json` `engines`, tag v5.7.284); the same range is stamped into the published `pdfjs-dist` manifest (`gulpfile.mjs:2694-2696`). This repo already pins Node 24.x (`package.json:14-15`, `.github/workflows/ci.yml:95`), so no second toolchain is needed. pdf.js installs with `npm ci` against a committed `package-lock.json` (947 `node_modules/` entries) and builds with `npx gulp dist` (`.github/workflows/publish_release.yml:33-36`). Its devDependencies include webpack 5, babel, core-js, terser, TypeScript, gulp 5 and puppeteer; `.puppeteerrc` sets `skipDownload: false` for Chrome and Firefox nightly, so a CI install must export `PUPPETEER_SKIP_DOWNLOAD=1` to avoid two browser downloads that `dist` never uses.

**Targets.** Every bundle is a webpack build of one entry (`createMainBundle` → `src/pdf.js` → `build/pdf.mjs`, `gulpfile.mjs:454-464`; `createWorkerBundle` → `src/pdf.worker.js` → `build/pdf.worker.mjs`, `:534-544`). `generic` (`:1261-1279`) and `generic-legacy` (`:1281-1299`) differ only in `SKIP_BABEL: false` for legacy, which switches on `@babel/preset-env` with `useBuiltIns: "usage"` (`:103-108`, `:316-326`). The `dist` task (`:2706-2833`) is `series(generic, generic-legacy, components, components-legacy, image_decoders, image_decoders-legacy, minified, minified-legacy, types, createDist)`. `createDist` assembles `build/dist/`: generated `package.json` (`:2659-2704`), `external/dist/**` (README, `webpack.mjs`, hand-written `.d.mts` shims), `LICENSE`, `cmaps/`, `iccs/`, `standard_fonts/`, `wasm/` from the generic build, `build/{pdf,pdf.worker,pdf.sandbox}.mjs(+.map)` (`:2763-2771`), the legacy twins into `legacy/build/` (`:2772-2780`), minified variants, `web/` from components (`pdf_viewer.mjs`, `pdf_viewer.css`, `images/`, `:1300-1321`, `:2803-2814`), `image_decoders/`, and `types/` from `tsc --emitDeclarationOnly` (`:1685-1693`, `tsconfig.json`). There is no `dist-pre` task at this tag; the only other dist-named task is `dist-install` (`:2835-2848`), which runs `npm install ./build/dist` into `PDFJS_INSTALL_PATH`.

**Version stamping.** `createBuildNumber` (`:1004-1041`) sets `version = pdfjs.config.versionPrefix + <commits since baseVersion>` (`pdfjs.config`: prefix `5.7.`, base `a40b91f0…`) and falls back to build 0 outside a git checkout. That string becomes `BUNDLE_VERSION` in every bundle (`:284-290`) and is checked at runtime: the worker refuses an API whose version differs (`src/core/worker.js:118-126`). A fork with N commits on top of the tag therefore builds as `5.7.(284+N)`, and all artifacts must come from one build. The repo already relies on that (`app/services/pdfjs/runtimeLib.ts:386-412` compares `pdfjsLib.version` against `public/pdf/.pdfjs-version`).

**Wasm and data inputs are in-tree**: `external/openjpeg/*.wasm`, `external/qcms/*.wasm`, `external/jbig2`, `external/quickjs` (`gulpfile.mjs:624-665`), bcmaps, ICC profiles and standard fonts; no native toolchain runs during `gulp dist`.

**Time.** Mozilla's release job (checkout, `npm ci`, `gulp dist`, `npm publish`) on `ubuntu-latest` took 1m44s for v5.7.284 (`gh run list -R mozilla/pdf.js --workflow publish_release.yml`: 19:23:20Z → 19:25:04Z) and 1m30s–2m25s for the five surrounding releases. Expect 2–4 minutes per fork build in this repo's CI including a cold `npm ci`.

**Output vs what this repo imports.** Imports resolve `pdfjs-dist` (161 sites), `pdfjs-dist/legacy/build/pdf.mjs` (16; SSR/Electron main via `runtimeLib.ts:10-14`), `pdfjs-dist/legacy/build/pdf.worker.mjs` (3; copied by `scripts/build-electron.mjs:117`), `pdfjs-dist/web/pdf_viewer.mjs` (2), `pdfjs-dist/types/...` (13), `pdfjs-dist/wasm`, `pdfjs-dist/package.json`. `scripts/copy-pdfjs-assets.mjs:21-118` reads `build/pdf.worker.mjs` (re-minified by esbuild, `:94-101`), `standard_fonts/`, `cmaps/`, `wasm/`, `iccs/` and `package.json.version`; `scripts/sync-pdfjs-viewer-css.mjs:15-28` reads `web/pdf_viewer.css` and `web/images`. So the repo needs `generic`, `generic-legacy`, `components`, `types` and the `createDist` assembly. The `minified`, `minified-legacy`, `image_decoders*` and `components-legacy` steps produce nothing this repo reads and could be dropped from a fork's task to shorten the build; the installed package is 35 MB, of which `legacy/` is 16 MB and `build/` 12 MB (mostly `.map` files).

## 2. Consuming a fork

pnpm's rule for git sources: "A Git-hosted dependency that ships sources rather than a built package has to be prepared — its dependencies installed and its build script run — before it can be installed" (pnpm docs, *Supported package sources*). pdf.js's root `package.json` has no `main`, no `prepare`, and is named `pdf.js`, so `"pdfjs-dist": "github:…/pdf.js#sha"` does not work without adding a `prepare` script that runs `gulp dist` and relocates output; and that would run webpack inside every `pnpm install` on every developer machine and CI job. That rules out the naive git-URL form and leaves three real options.

**(a) Submodule + build in CI.** Add `vendor/pdf.js` as a submodule pinned to the fork commit; a `scripts/build-pdfjs.mjs` step runs `npm ci && gulp dist` and points `pdfjs-dist` at `file:vendor/pdf.js/build/dist` (or copies it into a workspace package). Cost: a full checkout of the tag is 152 MB, of which `test/pdfs` is 122 MB (1,385 files) and `external+l10n+src+web` 12 MB; a sparse checkout excluding `test/` keeps it small. Every CI job that installs deps (`ci.yml` quality, unit and e2e jobs at `:133-154`, `:243-262`, `:290-300`; `release.yml:688`, `:775`, plus `build-target.yml` per OS) would need the build step or a cached artifact keyed on the submodule SHA, adding 2–4 minutes uncached to each. `patchedDependencies` (`package.json:318-320`, `pnpm-lock.yaml:95-98`) is removed outright because the dependency is no longer a registry package. Weakest fit: this repo's CI is time-budgeted (`timeout-minutes: 5/20/30/35`, `ci.yml:104,134,244,291`) and installs deps in many jobs.

**(b) Vendored built dist committed here.** Build once locally or in a fork-side workflow, commit `build/dist` into e.g. `vendor/pdfjs-dist/` (a workspace package; `pnpm-workspace.yaml` already lists `packages/*`) and set `"pdfjs-dist": "workspace:*"`. Cost: zero CI time, but roughly 35 MB per version in git history (drop `.map` files and unused `minified`/`image_decoders` to get near 10 MB), and no CI proof that the vendored bytes match the fork source unless a job rebuilds and diffs (the repo already does exactly this pattern for `pdfjs-viewer-sanitized.css` and `public/pdfjs/images`, `ci.yml:171-187`). `patchedDependencies` goes away; the lockfile `patchedDependencies` block disappears on the next install.

**(c) Fork published under a scope.** Copy Mozilla's `publish_release.yml` into the fork, change `DIST_NAME` in `packageJson()` (`gulpfile.mjs:2662`) to `@evb0110/pdfjs-dist`, publish on tag. Here: `"pdfjs-dist": "npm:@evb0110/pdfjs-dist@5.7.x"`. Cost: one publish workflow in the fork (about 2 minutes per release) and nothing in this repo's CI; install cost is unchanged from today because pnpm downloads a tarball. Keeps the alias name `pdfjs-dist`, so all 161+ import sites, `copy-pdfjs-assets.mjs`, and `scripts/build-electron.mjs` are untouched. Two things must be checked: `nuxt.config.ts:529-531` groups chunks by `/node_modules[\\/]pdfjs-dist[\\/]/` on the resolved real path, which for an aliased package is `.pnpm/@evb0110+pdfjs-dist@…/node_modules/@evb0110/pdfjs-dist/` and will not match without widening the regex; and `pnpm-workspace.yaml` `minimumReleaseAge: 10080` holds any newly published version for seven days unless the scope is added to `minimumReleaseAgeExclude`. This is the cheapest option for this repo and the one already implied by the ADR ("built into `pdfjs-dist` by this repo", `docs/architecture/adr/0002-…:32-34`) only if "by this repo" is read as "by our fork's workflow".

In all three, the same in-repo changes follow: delete `patches/pdfjs-dist@5.7.284.patch` and the `pnpm.patchedDependencies` entry; rewrite the tests that read the patch text (`tests/unit/architecture/xlargeDocumentPathArchitecture.test.ts:745-799`, and `tests/unit/app/modules/pdf-viewer/pdfjsEditToolbarRemovalGuard.test.ts:24-45`, which reads the installed bundles) to assert on the installed bundles or fork version instead; update the fourteen test files under `tests/` that hard-code `'5.7.284'` as a mock version; and regenerate `public/pdf/.pdfjs-version` via `copy:pdfjs`.

Source-port notes the bundle hides:

- Edit 14 tests `this.pdfManager instanceof NetworkPdfManager` inside `XRef`. `xref.js` does not import `pdf_manager.js` (`src/core/xref.js:16-33`), and `pdf_manager.js → document.js → xref.js` (`pdf_manager.js:31`, `document.js:81`) makes that import circular. In source, use a capability flag on the manager or `this.stream instanceof ChunkedStream` alone.
- Edit 16 declares the helper as a nested function between `handler.on` registrations; in source it belongs at module level in `worker.js`, and `UnknownErrorException` is already imported there (`:16-27`).
- The preprocessor strips `PDFJSDev.test("TESTING")` asserts from bundles (e.g. `chunked_stream.js:312-317`), so the patch hunks do not show them; the port must keep or extend them.
- Edits 9–12 remove every use of `this.bytes` in `ChunkedStream`; upstream unit tests in `test/unit/` that construct `ChunkedStream` will need the same treatment before the fork's `gulp unittestcli` passes.

## 4. `pdfjs-dist-codex-preview`

`package.json:170` aliases `pdfjs-dist-codex-preview` to registry `pdfjs-dist@5.4.296` (`pnpm-lock.yaml:218-220`), unpatched. Its only consumer is the diagnostic Electron harness `scripts/diagnostics/pdf-preview-compat-harness/main.mjs:31`, which serves `node_modules/pdfjs-dist-codex-preview/build/pdf.{mjs,worker.mjs}` and deliberately mirrors Codex's artifact preview (`getDocument({data})` without `wasmUrl`, `:50-54`), driven by `scripts/diagnostics/verify-generated-pdf.py:22`. No app, Electron, test or CI path imports it. A fork has no role to keep here: the alias must stay pinned to stock 5.4.296 precisely because it stands in for a third-party consumer, so it is untouched by the fork decision and must not be repointed at the fork.
